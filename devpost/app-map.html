Limnim · Project guide

From policy text to a clear guest answer.

Limnim verifies hotel cancellation deadlines against their exact policy wording, calculates the potential refund locally, and prepares a response hotel staff can review and copy.

Updated October 20, 2026 for the Limnim staff-response workflow. This local workspace update has not been published to the public repository.

One action through the app

A front-desk team member submits a policy and reservation details once. The server checks the model's evidence; the browser calculates the estimate and prepares a guest response.

OpenAI receives the pasted policy text and property time zone for the requested analysis. The booking amount and currency remain in the browser. The guest response is generated locally from validated rules and is never sent automatically. Unsupported or conflicting policy details block the live estimate and reply.

A 3-stop code route

Reference route · not toured interactively. Open these locations in the editor to follow the same flow as the diagram.

  1. Start where hotel staff act.

    src/components/booking-form.tsx collects policy and booking input. src/components/policy-workspace.tsx keeps the workflow, sample path, and live result together.

  2. Follow the server's evidence gate.

    src/app/api/analyze/route.ts calls the provider through createAnalyzeHandler. supportedRuleEvidenceIssue cross-checks the model's values against the source quote.

  3. Trace a verified rule to a guest-ready result.

    resolveRules and evaluatePolicy apply inclusive or strictly-after property-local boundaries; calculatePenalty and calculateRefund do decimal arithmetic. buildGuestResponse combines the result and evidence for review.

To change this, start here

  • Support another policy phraseStart with prompt.ts, then update the exact evidence rules in validate-analysis.ts and its tests.
  • Change how a deadline affects moneyStart with evaluate-policy.ts and money.ts; preserve inclusive, strict-after, and rounding checks.
  • Change the staff replyStart with guest-response.ts; keep amounts deterministic, quote the supporting policy, and preserve the estimate caveat.
  • Adjust the sample bookingEdit the fictional fixture in tokyo-policy.ts; it uses the same deterministic calculation path.
  • Change the visual treatmentStart with globals.css and the relevant component. Keep the native range input keyboard-accessible.

A practice to reuse

Make the evidence requirement testable before an AI output can drive a consequential result. Limnim's prd.md · Analysis and Rule Evidence requires exact policy evidence and a clear inclusive or strict-after boundary. tests/unit/validate-analysis.test.ts checks matching and mismatching dates, times, percentages, boundaries, and policy scope. In another AI-assisted project, define what an answer must prove, then test both the evidence that qualifies and the evidence that should leave the result unresolved.

Run the app again

The fictional Tokyo example works without an API key. Live analysis needs a server-side OPENAI_API_KEY; do not put the key in client code or commit .env.local.

npm install
cp .env.example .env.local
npm run dev

Then open http://localhost:3000. The code map is a local reference file at devpost/app-map.html; reopen it from the project folder or the editor.
